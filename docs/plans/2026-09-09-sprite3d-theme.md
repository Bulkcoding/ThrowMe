## 확정 요구사항과 의도 조정

1. 기존 모든 벡터 테마와 펫은 유지하고 설정에 별도 ‘3D 공’ 카드를 추가한다.
2. 최초의 Blender 스프라이트 요청은 인터뷰에서 변경되었다. 사용자가 우클릭 상하좌우 자유 회전을 요청했고, 다중 시점 시트 대신 실시간 렌더 재검토와 새 테마 전체 적용을 선택했다. 실시간 렌더를 검증하는 계획이며 이미 성능이 입증된 것으로 보고하지 않는다.
3. 슬라임 느낌 기본 모델 한 종류만 내장한다. 추가 모델·팩 가져오기 제외. 36프레임, 8열 시트, `sprite3d.json`, Blender 굽기 도구 및 프레임 인덱스 검사는 실시간 방식 채택 시 불필요하다. 이전 결정으로 되돌아가지 않는다.
4. 우클릭을 누르고 상하좌우로 움직여 다축 회전. 놓으면 마지막 회전 방향과 속도를 이어받아 감속. 짧은 우클릭은 기존 메뉴.
5. 사용자 이미지를 모델 정면에 부착하고 모델과 함께 회전·변형한다. 이미지 가져오기·그리기·팔레트·템플릿·크기·제거를 기존 기능으로 제공한다.
6. 충돌 세기 여섯 단계, 총 표시 200ms. 그림 전체의 2D 회전은 금지하고 3D 모델만 회전한다.
7. 자동 이동 지원, 통통 튀는 외형. 기존 이동 경로·모니터 제한·속도 설정을 재사용한다. 자동 이동 중 클릭 통과·직접 조작 금지 규칙 유지. 사용자가 추가 확인한 예외: 커서 키링은 기존 매달리기 유지, 다른 자동 이동에서 도약 표현. 직접 회전은 자동 이동을 끈 뒤 사용.
8. 여러 컴퓨터 방에서 미지원·표시 실패 상대는 젤리로 대체한다. 현재 신버전끼리는 3D 공과 부착 이미지가 전달되어야 한다.
9. 정지하면 현재 자세를 유지하고 움직임을 멈춘다. 스프라이트 대기 행 대신 관성 종료 후 정지 상태를 사용한다.

## 구조 결정

### 렌더와 모델

첫 선택은 WPF 내장 `Viewport3D`, `MeshGeometry3D`, `QuaternionRotation3D`. 외부 렌더 라이브러리·모델 로더를 추가하지 않는다. `Sprite3D = 9`는 사용자가 처음 지정한 직렬화 식별자를 유지한다. 사용자 표시명은 ‘3D 공’, 실제 구현명은 `Sprite3DSkin`으로 통일한다.

새 파일:

- `Views/Skins/Sprite3DSkin.xaml(.cs)`: 96×96 디자인, 고정 직교 카메라, 모델·재질·변환. 기본 구는 코드로 한 번 생성(경도 48, 위도 24분할 시작, 약 2천 삼각형 수준). 고정 메시·조명·재질은 가능한 경우 Freeze. 1개 Viewport, 환경광과 방향광 각 1개.
- `Animation/Sprite3DMotion.cs`: 표시와 분리된 자세·관성·찌그러짐 계산. 추상 기반형·인터페이스 계층은 만들지 않는다.
- `Views/SlimeWindow.Sprite3D.cs`: 창 입력과 스킨 연결. 기존 큰 파일에는 호출·등록·정리 지점만 추가한다.

외형은 민트색 둥근 슬라임, 광택과 정면 표식으로 회전이 식별되도록 한다. 기본 얼굴/표식은 코드 기반 고정 그림 재질로 만든다. 굴절·실시간 그림자·다층 투명 껍질은 넣지 않는다. 재질 불투명도 약 0.92를 출발점으로 검증하되 투명 오류가 보이면 불투명 광택으로 바꾸기 전에 외형 영향 설명과 사용자 확인을 받는다. 첫 검증 이미지에서 슬라임 느낌이 식별되어야 한다.

`Viewport3D.IsHitTestVisible=false`, 경계 여백 검증 후 `ClipToBounds=false`. 카메라와 조명은 공과 함께 돌리지 않는다. 3D 모델에만 자세 → 화면 기준 충돌 변형 → 도약 변형을 적용한다. 기존 공통 그림자와 과도하게 겹치지 않도록 3D에서는 공통 그림자를 조절하고 도약 그림자를 3D 스킨 안에서 처리한다.

### 회전과 입력 계약

- 단위: 각속도 deg/s, 시각 s, 이동 좌표는 기존 물리 픽셀. 원점·반지름은 실제 공 중심과 반지름으로 정규화해 화면 배율에 영향받지 않게 한다.
- 우클릭 시작은 공 원형 영역 내부, 3D 표시 중, 자동 이동 꺼짐, 좌클릭 잡기·당구 조준 없음, 창 소유/표시 상태에서만 가능.
- 상태는 대기 → 우클릭 후보 → 회전 중 → 관성. 시스템 최소 가로/세로 드래그 거리를 현재 화면 배율에 맞춰 판정한다. 문턱 이전에는 메뉴 후보, 이후에만 마우스 캡처하고 메뉴 열림을 억제한다. 버튼을 놓을 때 후보면 메뉴 한 번, 회전 중이면 메뉴 없이 관성 시작.
- 공을 가상 구에 투영해 직전·현재 벡터의 외적 축과 각도로 Quaternion을 누적한다. 화면 Y 증가와 3D Y 증가가 반대임을 명시 변환한다. 구 밖은 원 경계로 정규화한다. 같은 점·반대점·길이 0·NaN/Infinity를 처리한다.
- Quaternion은 누적 때 정규화. 마지막 약 80ms 입력으로 각속도를 구하고 `MaxAngularVelocity`로 크기를 제한한다. 놓은 뒤 `exp(-SpinFriction*dt)` 감쇠와 `SpinStopThreshold`를 재사용한다.
- 후보 단계에서는 이동·스핀을 변경하지 않는다. 문턱을 넘어 실제 회전에 진입할 때만 기존 평행 속도·AngularVelocity·SurfaceSpin과 자유 회전 관성을 0으로 만들고 SpinAngle의 차분 기준을 현재 값으로 재동기화한다. 현재 3D 자세는 보존한다. 조작 중에는 가상 구 회전만 반영하며 기존 물리 스핀을 별도로 더하지 않는다. 놓은 뒤 평행 속도는 0이고 자유 회전 관성만 시작한다. 회전 조작 자체는 던지기를 만들지 않는다. 이후 좌클릭 던지기는 기존 동작이다.
- 자동 이동 활성화·일시정지·숨김·테마 교체·포커스/캡처 상실·종료·네트워크 소유권 이동 시 진행 중인 우클릭 입력 상태를 정리한다. 의도적 버튼 놓기만 관성을 시작하며 입력 취소는 관성 0. 이미 손을 놓고 관성이 진행 중인 상태에서의 일시정지는 관성을 동결하고 재개 시 이어간다. 좌우 동시 입력에서는 먼저 시작한 조작을 우선한다.
- 평소 던지기는 이동거리/반지름으로 회전량을 정하고 화면 법선 `(0,0,1)` × 화면 이동벡터 `(vx,-vy,0)`의 외적으로 구름 축 `(vy,vx,0)`을 만든다. 왼쪽/오른쪽·위/아래가 반대로 구르는지 정면 표식으로 검증한다. 기존 물리 `SpinAngle`은 차분만 더해 별도 화면 법선 스핀으로 반영하며 초기화 시 기준각도도 동기화해 자세 점프를 방지한다. 각속도를 물리와 시각 양쪽에서 중복 적분하지 않는다.
- 자유 회전 각속도는 3D 표시 전용이며 기존 Magnus/벽 반사 물리를 다축으로 변경하지 않는다. 기존 2D 스핀은 계속 기존 물리에 사용한다.

### 충돌·유휴·자동 이동

- `_dizzyUntil`은 기존 어지러움 시간이다. 200ms 변형 타이머로 재사용하지 않는다.
- `ImpactTier.None`이면 변형 없음. 나머지는 `min(5,floor(clamp(Intensity01,0,1)*6))`으로 단계 0~5. 최소 축척 `{0.90,0.84,0.78,0.72,0.66,0.60}`. 충돌 법선 방향 압축, 직교 방향은 최대 1.2까지만 확장. 재충돌은 현재 시점에서 새 세기와 200ms를 적용한다.
- 0~40ms에 목표 압축으로 진입, 40~100ms 유지, 100~200ms 원형 복귀. 마지막 시점은 정확히 기본값. 충돌이 도약 변형보다 우선하며 원형 복귀 시 남아 있는 도약 위상으로 이어간다.
- `HasActiveMotion`은 우클릭 조작·관성·충돌 복구·활성 도약 여부를 반영한다. OnRendering의 정상·드래그·일시정지 경로 각각 처리. 정지 시 반복 구독·타이머 없음. 일시정지는 관성을 동결하고 재개 시 경과시간 점프 없이 진행한다. 숨김은 루프를 중단한다.
- 자동 이동 경로와 추진력은 기존 함수를 재사용한다. `ApplyCrawlShape`에서 3D는 젤리의 크기/기울기 대신 위상과 진행 여부만 전달. 키링은 위상 도약 없이 기존 추종 위치를 따른다.
- 도약은 기존 물리 중심 주위 시각 높이로 표현한다. 공 전체를 물리적으로 다시 적분하지 않는다. 정규 위상에서 `height=0.10*diameter*sin(pi*t)`(0≤t≤1), 착지 전후 약한 3D 압축·그림자 변화를 적용. 카메라 여백·최대 크기에서 잘리지 않게 한다. 자동 이동 중 입력 금지이므로 시각 도약과 클릭 중심 차이는 직접 조작에 영향을 주지 않는다. 꺼지는 즉시 높이·변형 0.
- AppSettings의 양방향 테마/자동 이동 제한과 설정 잠금·안내를 함께 수정한다. 젤리의 기존 기어다니기와 키링은 변경하지 않는다.

### 사용자 이미지와 오류 경계

- `SkinImageStore.Supports`에 Sprite3D 추가. 저장·그리기·템플릿 기능을 재사용한다. 3D 선택 시 `CustomImageLayer`는 숨기고 스킨에 `BitmapSource?`와 배율을 전달한다. 자동 이동 중에도 3D 이미지 유지.
- 이미지 정면은 모델 로컬 +Z. 구면 앞쪽에 밀착된 패치 메시 또는 구의 앞면 UV 재질로 표현하고 뒷면에는 복제하지 않는다. 분리 패치라면 반지름 오프셋을 아주 작게 두고 깊이 충돌 검증. 본체와 동일한 회전·압축 적용. 평면 카메라 덧씌우기는 불허.
- 기존 배율 0.2~2.0, 기본 1.0은 앞면 범위에 맞추고 범위 초과분을 잘라낸다. 이미지는 비율 유지·투명 영역 유지. 미리보기와 실행 화면에서 같은 매핑을 사용한다.
- 파일 없음은 기본 얼굴. 존재하지만 해독 실패는 로그와 기본 젤리 표시(선택값·원본 이미지 삭제 금지). 이미지 수정·제거 또는 테마 재선택 때 재시도. 모델 초기화 실패도 동일. 실패한 3D를 매 프레임 재생성하지 않는다.
- `SkinImageStore.Load`의 null만으로는 파일 없음과 해독 실패를 구분할 수 없다. 경로/존재 확인과 읽기 결과를 함께 판정하고 접근 거부는 실패로 취급한다. 현재 `Has`가 예외를 false로 바꾸는 점도 고려해 3D 오류 판정에 그대로 의존하지 않는다.
- 실패 대체는 창의 실제 표시 상태로 판정한다. 선택값 9를 보존하더라도 실제 JellySkin이면 3D 입력·재질 업데이트를 중단하고 젤리의 Rigid/Upright·이미지층·자동 이동 표현으로 일관되게 처리한다. 선택값을 바꿔 방장에게 다시 전송하는 순환을 만들지 않는다. 이미지 수정·제거 알림은 실패 상태일 때도 스킨 재생성 재시도를 깨워야 한다.
- 새 3D 이미지 수신/읽기 경계에서 파일 크기·해독 픽셀수·지원 형식·유한 배율 확인. 로컬 가져오기는 원본 8MiB 이하·한 변 4096 이하·총 16,777,216픽셀 이하를 해독 전 메타 검사하며 현재 가져오기에서 지원하는 형식만 사용한다. 새 이미지 형식은 추가하지 않는다. 저장은 긴 변 512 이하로 축소. 방 이미지는 base64 해독 전 문자열 길이 제한, 해독 후 기존 600KiB 한도와 최대 512×512를 준수하고 PNG만 수용한다. 원자적 저장을 재사용하고 실패 시 기존 파일을 덮어쓰지 않는다.

### 방 호환과 자세 전달

기존 코드에서 `Enum.TryParse("Sprite3D")`는 구버전에서 실패하여 이전 테마가 남는다. 대신 3D일 때만 SET_THEME/ROOM_STYLE의 테마 문자열을 숫자 문자열 `"9"`로 보낸다. .NET의 숫자 열거형 파싱은 미정의 값도 받아들이며 기준 1.29.0의 `ApplySkin` 기본 분기가 JellySkin이다. 다른 테마는 기존 문자열 그대로. 구버전 실행/수신 하네스로 이 동작을 반드시 증명한다. 기본값 반환 가정만으로 완료 처리 금지.

- 신버전 수신은 `"9"`/`"Sprite3D"` 모두 Sprite3D로 인식, 다른 미정의 값은 젤리로 정규화하고 로그. 로컬 선택은 `Sprite3D=9`, 방 표시는 ‘3D 공’.
- 이미지 대상은 `"Sprite3D"`로 보낸다. 구버전은 모르는 이름이라 저장하지 않고 젤리 표시. 신버전만 검증 후 수신한다. 구버전으로 대체될 때 로컬 젤리 이미지가 표시될 수 있으므로 3D 방 메시지 수신 시 기존 `SkinImageEnabled` 처리까지 기준 구버전으로 검증하고 수용 기준은 젤리 테마 대체로 한정한다.
- HANDOFF에는 선택적 quaternion 4수와 자유 회전 각속도 3수 필드를 추가한다. DTO는 배열 길이·모든 유한값·노름·각속도 한도 검증. 없거나 잘못되면 단위 자세/관성 0, 기존 SpinAngle 기준 재동기화. 신버전끼리는 자세 이어짐, 구버전을 거치면 추가 자세 손실을 허용하고 젤리 대체를 유지한다.
- `BallHandoffCoordinator`에 단순 상태 캡처/복구 콜백 연결 또는 기존 DTO 연결 지점을 사용한다. 별도 통신 계층 금지. 발송 전 회전 상태 저장, 거절·시간 초과는 원 상태 복구, 성공·숨김은 관성 중단. 중복 수신은 기존 handoffId 멱등성 준수.
- 서버는 data를 그대로 전달하므로 서버 코드·프로토콜 버전·배포는 변경하지 않는다. 실제 서비스 접속 없이 직렬화 및 로컬 중계 하네스로 확인.

## 실행 작업

모든 작업은 아래 순서로 수행한다. 공통 완료 기준은 변경 파일·수행 명령·결과·남은 제약을 기록하는 것이다. 기존 파일 CRLF, 새 파일 LF, UTF-8을 보존한다. Windows Forms와 충돌하는 타입은 `System.Windows.*` 별칭을 사용한다. 새 스타일은 `Resources/Theme.xaml`에 존재하는 키만 사용한다.

### 작업 1 — 격리와 렌더 시제품 관문

- 파일: `Services/AppPaths.cs`, `Views/SlimeWindow.xaml.cs`, 필요 시 `Views/SlimeWindow.Pet.cs`, `Services/PreviewRenderer.cs`, 신규 `Sprite3DSkin`과 `Sprite3DMotion`의 최소 렌더 부분, 프로젝트 버전/변경 이력.
- 실제 데이터 접근 전에 설정 가능한 내부 `AppPaths.DirOverride`를 추가한다. 절대 경로만 허용하고 첫 경로 접근 이후 변경은 금지. 지정되면 기본 경로 탐색·이관 없이 그 루트만 사용한다. 시험 프로세스별 별도 `%TEMP%` 폴더를 사용한다. 단순 스킨 생성 검증은 App 전체 시작을 피한다.
- %TEMP% 아래 .NET 8 콘솔/UseWPF 하네스로 ThrowMe.dll 참조. STA 스레드, 투명 창과 동일 크기·그림자·이동 경로. 모형+이미지+회전+최대 압축을 먼저 표시한다.
- 내부 DirOverride는 하네스에서 반사로 첫 접근 전에 지정한다. 하네스는 `App.OnStartup`을 실행하지 않고 필요한 리소스와 스킨을 직접 구성한다. `PreviewRenderer`의 기존 저장/배치 로직을 재사용해 정적 3D 장면을 추가하고, 실제 창 검증은 별도로 수행한다.
- 실제 SlimeWindow 하네스에는 내부 검증용 생성 경로(기존 공개 생성자는 기본 동작 유지, 내부 생성자에 `enableExternalIntegrations=false`)를 둔다. 검증 경로는 생성자·OnSourceInitialized·설정 변경·종료 전체에서 AuthService/릴레이 시작, CLI 서버와 ClaudeHooksInstaller의 설치 및 제거, 전역 단축키/마우스 훅 등록, 사용 안내 토스트를 건너뛴다. `CliLinkEnabled=false`만으로는 훅 제거가 실행되므로 충분하지 않다. 렌더·입력·물리·오버레이는 유지하며 SoundEnabled=false를 주입한다. 창 종료 후 같은 경로의 해제만 수행한다.
- 게시 DLL도 이 격리 하네스 경로로 호스팅해 산출물의 창·리소스를 검증한다. 이는 정상 EXE 시작 경로 전체 검증과 다르므로 결과에 구분해서 기록한다. 사용자 앱·사용자 훅 설정을 바꾸는 정상 실행은 하지 않는다.
- 새 라이브러리 없이 기본 재질, 메시, 3D 변형과 이미지 밀착을 검증한다. 화면 밖 Left=-4000의 RenderTargetBitmap PNG는 정적 품질 확인용이며 성능 증거로 사용하지 않는다. 성능은 보이는 투명 창에서 실제 렌더·이동으로 측정한다.
- 60Hz 기준 동일 기기·공 크기·효과 조건에서 젤리와 3D를 각각 60초 측정: 이벤트 간격 95백분위 25ms 이하, 100ms 초과 정지 0회, 3D 평균 CPU가 젤리 대비 전체 CPU 5%p 이내 증가, 정지 5초 내 렌더 구독 해제. 기기·GPU·렌더 등급·화면 배율·측정 방식 기록. 고주사율이면 60Hz 이상 처리되되 이 기준을 최소 기준으로 사용한다.
- 100/150/200% 배율과 최소·최대 공 크기에서 잘림·검은 배경·투명 정렬·거꾸로 된 이미지 없음. 자유 회전 후에도 이미지가 표면을 따라야 한다.
- 실패하면 종속 작업을 진행하지 않는다. 메시·재질 수를 줄이는 한 차례 제한적 조정 후 다시 측정하고, 여전히 실패하면 결과를 보고하고 렌더 방식/품질 변경을 사용자에게 확인한다. 묵시적으로 스프라이트나 외부 엔진으로 변경하지 않는다.
- 기능 버전은 첫 제품 변경에서 `1.30.0`, Assembly/FileVersion `1.30.0.0`. 같은 기능 작업마다 불필요하게 버전을 더 올리지 않고 모든 변경을 동일 버전 한국어 최상단 항목에 누적한다.

- 구버전은 별도 시험 복사본에만 경로 격리와 외부 연동 차단을 적용한다. 제품 저장소의 구버전 분기나 기존 실행 파일을 수정하지 않는다. 구버전 테마 파싱·AppSettings.Skin·ApplySkin·UpdateSkinBehavior 코드는 원문 그대로 유지하여 검증 대상 행동을 바꾸지 않는다. 시험 변경 차이를 기록한다. 정상 App 시작 대신 격리된 STA 하네스로 이 경로를 호출하고 창 생성·표시·종료에서 훅 설치/제거, 릴레이, 전역 단축키가 실행되지 않음을 확인한다.
