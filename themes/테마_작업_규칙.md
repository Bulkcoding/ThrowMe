# ThrowMe 테마 개발 규칙 (멀티 세션)

> 이 문서는 **main(통합) 세션이 정한 규칙**이다.
> 각 테마를 개발하는 세션은 **작업 시작 전에 이 문서를 반드시 먼저 읽고** 그대로 따른다.
> 새 스킨(축구공·농구공 등)을 하나씩 별도 세션/브랜치에서 병렬 개발하기 위한 약속.

---

## 0. 큰 그림

- **1 테마 = 1 브랜치 = 1 워크트리(폴더) = 1 세션.**
- `main` 브랜치가 **기준점이자 통합 지점**. 모든 테마 브랜치는 `main`에서 갈라지고, 완료되면 `main`으로 merge.
- 각 세션은 **자기 폴더 안에서만** 작업한다(다른 테마 폴더를 건드리지 않는다).

---

## 1. 브랜치 / 폴더 만들기

테마마다 `main` 폴더(`C:\claudeProject\Slimely\ThrowMe`)에서 아래처럼 워크트리를 딴다.

```powershell
git worktree add -b theme/<슬러그> ../ThrowMe-<슬러그> main
```

예:
```powershell
git worktree add -b theme/soccer     ../ThrowMe-soccer     main
git worktree add -b theme/basketball ../ThrowMe-basketball main
```

그 다음 **새로 만들어진 폴더**(`../ThrowMe-soccer`)에서 새 Claude 세션을 열어 작업한다.

| 항목 | 규칙 | 예: 축구공 | 예: 농구공 |

## 3. 새 테마가 건드리는 파일

### 신규 파일 (충돌 없음 — 자유롭게 생성)
- `src/ThrowMe/Views/Skins/<파스칼>Skin.xaml`
- `src/ThrowMe/Views/Skins/<파스칼>Skin.xaml.cs`
  - 기존 스킨(`BilliardSkin`, `BallSkin`, `JellySkin`) 구조를 참고.
  - 단단한 공이면 `Rigid`(찌그러짐 없음), 표정/클릭 이펙트가 필요하면
    `ISkinExpressions` / `ISkinClickEffect` 구현.

### 공유 파일 4곳 (⚠ 충돌 핫스팟 — append 규칙 준수)
여러 테마 세션이 **똑같은 4곳**을 건드리므로 merge 충돌이 나기 쉽다.
**기존 줄은 절대 수정하지 말고, 항상 맨 끝에 한 줄만 추가(append)** 한다.

1. `src/ThrowMe/Models/SlimeSkinKind.cs`
   - enum **맨 끝**에 값 추가. 번호는 **4절 예약표**에서 배정받은 값을 명시.
   ```csharp
   /// <summary>축구공 — 검정/흰 오각형 패턴.</summary>
   Soccer = 5,
   ```

2. `src/ThrowMe/Views/SlimeWindow.xaml.cs` → `ApplySkin()`
   - switch 의 마지막 case(`_ => new JellySkin()`) **바로 위**에 자기 case 추가.
   ```csharp
   SlimeSkinKind.Soccer => new SoccerSkin(),
   ```

3. `src/ThrowMe/Views/SettingsWindow.xaml.cs` → `Skins[]` 배열
   - 배열 마지막 원소 뒤에 추가.
   ```csharp
   (SlimeSkinKind.Soccer, "축구공"),
   ```

4. `src/ThrowMe/Views/SettingsWindow.xaml.cs` → `MakeSkin()`
   - switch 의 기본 case 위에 추가.
   ```csharp
   SlimeSkinKind.Soccer => new SoccerSkin(),
   ```

> 이렇게 해도 같은 지점이라 merge 충돌이 날 수 있다. **충돌 해결은 main(통합) 세션이 담당**하니,
> 각 세션은 "자기 것 한 줄만 append" 원칙만 지키면 된다.

## 3.5 테마별 특수 요구사항 (해당되면 필수)

- **골대 · 네트가 있는 테마(농구공 · 축구공 등)**: 골(득점)이 들어갔을 때,
  **공의 충격 방향과 세기에 맞춰 그물(net)이 흐늘거리며 출렁이도록** 반드시 표현한다.
  - 공이 그물을 그냥 통과하는 게 아니라, 그물이 충격을 받아 **늘어졌다가 서서히 되돌아오는**
    물리적인 느낌(관성·감쇠)을 살린다.
  - 충격이 셀수록 그물이 더 크게 출렁이고, 약하면 살짝만 흔들리게 세기를 반영한다.

## 3.6 숨기기 단축키 대응 (⚠ 모든 테마 필수)

> **"빠르게 숨기기" 단축키(기본 `Alt` + `` ` ``)를 누르면 공만 사라지는 게 아니라,
> 그 테마가 화면에 띄운 것이 하나도 남김없이 전부 같이 사라져야 한다.**

숨기기의 목적은 **"화면에서 흔적을 완전히 없애는 것"**(누가 볼 때 즉시 감추기)이다.
공은 사라졌는데 골대·핀·레인 같은 게 덩그러니 남아 있으면 숨긴 의미가 없다.

### 반드시 함께 숨겨야 하는 것
그 테마가 만든 **모든 창 · 오버레이 · 부수 오브젝트**:

| 테마 | 함께 숨겨야 할 것 |
|------|-------------------|
| 당구공 | 3구 / 4구로 놓은 공들(`_extraBalls`) |
| 농구공 | 농구골대 · 백보드 · 그물(`_hoops`) |
| 볼링공 | 볼링핀(`_pins`) · 레인/거터/점수판 오버레이(`_lane`) |
| 공통 | 파티클 · 타격 문구 등 이펙트 오버레이 |
| _(새 테마)_ | **그 테마가 새로 띄우는 창은 전부 여기에 해당** |

### 구현 위치
`Views/SlimeWindow.xaml.cs` 의 **`ApplyVisibility()`** 한 곳에서 처리한다.
새 테마가 창(Window)을 새로 띄운다면, **그 창을 `ApplyVisibility()` 에 반드시 추가**한다.

```csharp
private void ApplyVisibility()
{
    bool show = _settings.SlimeVisible;
    ...
    // 새 테마가 띄운 창도 여기에 한 줄 추가 (append)
    foreach (var x in _myThemeWindows)
        { try { if (show) x.Show(); else x.Hide(); } catch { } }
}
```

### 규칙
1. **숨김**: `SlimeVisible == false` → 그 테마가 띄운 창을 **전부** `Hide()`.
2. **복원**: 다시 보이기 하면 **숨기기 직전 상태 그대로** 복원한다.
   (핀이 쓰러져 있었으면 쓰러진 채로, 점수·프레임도 유지 — 숨겼다고 게임이 초기화되면 안 된다.)
3. **닫지 말 것**: `Close()` 가 아니라 `Hide()` 다. 닫으면 상태가 날아간다.
4. 숨긴 동안에는 물리·렌더 루프도 돌 필요가 없다(유휴 CPU ≈ 0 유지).

### 검증 (테마 완료 전 필수)
- [ ] 테마 오브젝트를 화면에 띄운 상태(3/4구 놓기, 골대 세우기, 볼링 시작 등)에서
      숨기기 단축키를 누르면 **화면에 아무것도 남지 않는다**
- [ ] 다시 누르면 **숨기기 직전 상태 그대로** 되돌아온다
- [ ] 숨긴 동안 CPU ≈ 0

## 5. 각 테마 MD 파일 (필수 산출물)

- **위치**: `themes/<슬러그>.md`
- **작성자**: 그 테마를 개발하는 세션이 **작업하면서** 직접 작성·갱신한다.
- **양식**: `themes/_템플릿.md` 를 복사해서 사용.
- 무엇을 만들었고, 어떤 파일을 건드렸고, 어떻게 검증했는지 정리한다.

### ⚠ 읽기 규칙 (중요)
- 이 `themes/*.md` 파일들은 **평소에 자동으로 읽지 않는다.**
- **사용자가 "읽어줘"라고 지시할 때만** 읽는다.
- 즉, 각 테마 세션은 자기 테마 MD를 **쓰기만** 하고, 다른 테마 MD를 열어볼 필요 없다.

## 6. 완료 / 검증 / 통합 절차

각 테마 세션은 작업을 마치면:

1. `dotnet build src/ThrowMe/ThrowMe.csproj -c Debug` → **0 경고 / 0 오류** 확인.
2. 앱 실행해서 설정창 → 자기 테마 칩 선택 → 정상 표시·상호작용 확인.
3. `themes/<슬러그>.md` 최신화.
4. 커밋 (메시지는 한글 컨벤션, 예: `테마: 축구공 스킨 추가`).
5. **main(통합) 세션에 "머지해달라"고 알린다.** merge·충돌 해결은 main이 한다.

각 단계에서 **항상 빌드·실행 가능 상태**를 유지한다.

### ⚠ 검증 규칙 (모든 세션 필수)

> **다 만들었다고 바로 끝내지 않는다. 반드시 검증을 "여러 번" 반복한다.**

- 완성 후 **한 번만 확인하고 넘어가지 말고, 여러 번 반복 검증**한다.
  (빌드 → 실행 → 실제 동작 확인을 반복해서, 매번 같은 결과가 나오는지 본다.)
- 검증에서 **문제가 하나라도 발견되면, 끝난 게 아니다.**
  → **수정한 뒤 다시 처음부터 검증**한다.
- 이 과정을 **검증이 완전히 통과할 때까지 반복**한다.
- "대충 되는 것 같다"로 넘기지 말고, 요구사항(예: 골대 그물 출렁임)이
  **의도대로 정확히 동작하는지**까지 확인한 뒤에야 완료로 본다.

## 7. 다른 PC에서 환경 재현 (clone + worktree)

> **worktree 폴더 구조는 `git clone` 으로 따라오지 않는다.**
> git 이 전송하는 건 **커밋과 브랜치**뿐이고, "어느 폴더에 어느 브랜치를 펼쳤는지"는
> 그 PC 로컬 설정이라 저장소에 담기지 않는다.
> → 다른 PC에서는 **브랜치를 받아서 worktree를 다시 만들면** 똑같은 구조가 된다(내용은 동일).

### 7.1 작업하던 PC에서 (브랜치를 원격에 올리기)

worktree 브랜치는 로컬에만 있으므로, 다른 PC에서 이어서 작업하려면 **먼저 push** 해야 한다.

```powershell
git push -u origin theme/<슬러그>
```

예:
```powershell
git push -u origin theme/basketball
git push -u origin theme/bowling
```

### 7.2 다른 PC에서 (clone 후 폴더 재구성)

```powershell
# 1) clone — 이 폴더가 main(기준/통합) 이 된다
git clone https://github.com/Bulkcoding/ThrowMe.git ThrowMe
cd ThrowMe

# 2) 원격 브랜치 정보 가져오기
git fetch origin

# 3) 테마별 worktree 폴더 재생성 (원격 브랜치를 추적)
git worktree add --track -b theme/basketball ../ThrowMe-basketball origin/theme/basketball
git worktree add --track -b theme/bowling    ../ThrowMe-bowling    origin/theme/bowling
```

결과 — 원래 PC와 동일한 구조:
```
ThrowMe\              main             (기준/통합)
ThrowMe-basketball\   theme/basketball
ThrowMe-bowling\      theme/bowling
```

### 7.3 구분해서 쓸 것

| 상황 | 명령 |
|------|------|
| **기존** 테마를 다른 PC에서 이어서 작업 | `git worktree add --track -b theme/<슬러그> ../ThrowMe-<슬러그> origin/theme/<슬러그>` |
| **새** 테마를 처음 시작 (1절과 동일) | `git worktree add -b theme/<슬러그> ../ThrowMe-<슬러그> main` |

- 이미 로컬에 같은 이름의 브랜치가 있으면 `-b` 를 빼고
  `git worktree add ../ThrowMe-<슬러그> theme/<슬러그>` 로 붙인다.
- 현재 워크트리 목록 확인: `git worktree list`
- 폴더 정리: `git worktree remove ../ThrowMe-<슬러그>`
